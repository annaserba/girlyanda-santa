# Проверки

Используйте Node.js 22 и зависимости из `package-lock.json`.

- `npm run typecheck`: TypeScript.
- `npm test`: алгоритмы колец, запреты пар, анкеты, права, обработчики API,
  импорт, телефон и города, SSR интерфейса, геометрия карты, анимация и CI/CD.
- `npm run test:db`: жизненный цикл с реальными миграциями и PostgreSQL,
  только в отдельной базе `santa_verification`.
- `npm run build`: production-сборка Next.js.

При последней проверке выполнены проверка типов, 363 unit/SSR-теста,
36 интеграционных тестов в изолированной PostgreSQL и production-сборка.
При последней локальной сборке Docker Hub отвечал тайм-аутом; сборочные команды
выполнены без сети на ранее загруженных образах Node.js 22 и зависимостях проекта.
Результаты автоматических проверок не заменяют визуальную приёмку.

Для частного серверного комплекта отдельно проверены установка на пустую
PostgreSQL, восстановление пяти администраторов с неизменными хешами паролей,
отсутствие перенесённых сессий и анкет, отказ повторного SQL-импорта и повторный
запуск установщика с сохранением аккаунтов. Проверки используют отдельные
контейнеры и тома; рабочая база не изменяется. Клиентский вход проверяется
с текущим адресом браузера, отличным от адреса сборки.

## Ручная приёмка

Проверка в браузере остаётся необходимой и не заявлена как выполненная.
Проверьте главную, регистрацию, вход, личный кабинет, организатора и координатора
на широком экране, телефоне и в альбомной ориентации.

Проверьте поиск и выбор города мышью и клавиатурой, фокус и сообщения об ошибках,
ФИО получателя (отчество при наличии) в регистрации и анкете,
ввод телефона РФ и порядок полей. Площадка обязательна для «Рядом» и необязательна
для «Страны»; проверьте переключение трека и отказ сервера при пустой площадке в «Рядом».
Для площадки проверьте поиск, добавление нового названия, смену города и сброс выбора.
После сохранения анкеты проверьте просмотр всех ответов, открытие редактирования,
сохранение и отмену изменений. Уже поданную анкету можно менять при закрытом приёме
до фактической жеребьёвки; новую подтвердить нельзя. После жеребьёвки остаётся
только просмотр, включая аккаунты без назначенной пары. Пожелания необязательны.
В настройках организатора проверьте переименование и объединение: анкеты и права
координаторов должны обновиться, а подарочные пары остаться прежними.
В `/garland` проверьте выбор города, поиск по ФИО, пару даритель/получатель
и состояния подарков. Страница должна быть доступна только администраторам;
для гостей, участников и координаторов закрыта даже при включённой публикации
общей карты. На главной ФИО и пары не должны появляться и при входе администратора.
На карте проверьте плавность кольца, читаемость подписей, анимацию при загрузке
и ручную паузу. Персональные сведения не должны появляться на публичной карте.

Перед рассылкой проверьте ссылку на кабинет из внутренней сети и лимит BCC
вашего почтового клиента. Перед включением CD проверьте доступы платформы
и раскрытый GitLab pipeline в целевом контуре.
