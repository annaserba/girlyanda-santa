# Гирлянда Тайного Санты

Русскоязычное приложение для новогоднего обмена подарками между коллегами.
Работает во внутренней сети: карта, справочник городов, значки и оформление
включены в проект и не требуют внешних сервисов.

## Возможности

- Регистрация по электронной почте и паролю, телефон РФ и город с поиском.
- Добровольная анкета: ФИО получателя (отчество при наличии), трек «Рядом» или «Страна», необязательные пожелания, площадка обязательна для «Рядом», смена — по желанию.
- Площадки с поиском и добавлением новых. Регистр букв не создаёт дубликаты; организатор может переименовывать и объединять площадки одного города.
- Отдельные локальные кольца и межгородское кольцо: каждый дарит и получает один подарок; подарки себе и взаимные пары запрещены.
- Личный кабинет с просмотром поданной анкеты, редактированием до жеребьёвки, её результатом и отметками об отправке и получении.
- Кабинеты организатора и координатора, импорт участников, контроль задержек и резервных подарков.
- Обезличенная карта на главной; `/garland` — карта организатора с ФИО, парами и статусами, доступная только администраторам.
- Общее письмо через `mailto:` и BCC. Отправляет пользователь из почтового клиента; приложение не подключается к SMTP и не подтверждает доставку.
- Название сайта, бюджет, сроки и публикация карты настраиваются организатором.

Создание аккаунта не подтверждает участие. Получатель определяется жеребьёвкой
организатора после сбора анкет; добавление новой анкеты не меняет ранее выданные результаты.
Для каждого кольца нужно минимум три совместимых участника.

## Быстрый запуск

Нужны Docker и Docker Compose.

```bash
cp .env.example .env
openssl rand -hex 24
openssl rand -base64 32
```

Первую случайную строку сохраните в `POSTGRES_PASSWORD`, вторую — в
`BETTER_AUTH_SECRET` внутри локального `.env`. Заполните `ADMIN_EMAIL` адресом
организатора и задайте одинаковые `BETTER_AUTH_URL` и `NEXT_PUBLIC_APP_URL`.
Для локального запуска подойдёт `http://localhost:3000`.

```bash
docker compose up -d --build
```

Приложение откроется на [localhost:3000](http://localhost:3000).
Миграции выполняются при старте; PostgreSQL хранит данные в Docker volume.
Порты по умолчанию доступны только на локальном компьютере.
Для других портов задайте `APP_PORT` и `POSTGRES_PORT` в `.env`.

Зарегистрируйте организатора первым, до открытия доступа участникам:
первый аккаунт автоматически получает права администратора.
Адрес из `ADMIN_EMAIL` также получает эту роль при регистрации.
Подтверждения владения почтой в этой версии нет.

Для работы в сети настройте адрес, HTTPS и доступ через внутренний прокси.
`NEXT_PUBLIC_APP_URL` задаётся до сборки образа; после смены адреса нужна пересборка.
Сборка требует доступа к зависимостям либо заранее подготовленного внутреннего зеркала.
Готовый образ работает без доступа к интернету.

## Разработка и проверки

Нужны Node.js 22 и PostgreSQL. Установите зависимости через `npm ci`,
заполните `.env`, включая `DATABASE_URL` для вашей локальной базы, затем:

```bash
npm run db:migrate
npm run dev
npm run typecheck
npm test
npm run build
```

Интеграционные тесты изменяют данные только в отдельной базе с именем
`santa_verification`. Перед запуском `npm run test:db` укажите её в
`DATABASE_URL`; рабочую базу использовать нельзя.

GitHub Actions выполняет проверку типов, unit/SSR-тесты, интеграцию с PostgreSQL
и production-сборку. Корпоративный GitLab CI/CD с Helm, Vault и Argo CD описан
в [docs/cicd.md](docs/cicd.md); автоматическое развёртывание по умолчанию выключено.
